# AutoPostTG

AutoPostTG — веб-приложение, в котором AI-агент ведёт Telegram-канал по
контент-плану: человек задаёт план, агент пишет посты и подбирает к ним
изображения.

## Цель и задачи

Цель проекта — снять с SMM-специалиста рутину написания постов, оставив за ним
контроль над темами, планом и публикацией.

Система:

- хранит контент-план проекта: слот = дата публикации, рубрика и тема;
- по слоту плана генерирует текст поста и подбирает изображение из пула
  проекта;
- прогоняет пост через слои проверок: формальные правила, следование
  инструкциям проекта, отсутствие выдуманной конкретики, соответствие
  изображения тексту;
- отдаёт пост редактору на ревью либо публикует сам, если все проверки зелёные;
- показывает план в виде списка, недели и месяца, очередь, ошибки и историю
  операций.

Вся проверяемая конкретика поста должна быть в теме слота: агент не
придумывает факты и не заимствует их из соседних слотов плана.

Проект равен одному Telegram-каналу и принадлежит одному пользователю.
Совместной работы над проектом нет.

Подробности: [трейс задачи](docs/smm-agent/trace.md),
[контракт API](docs/smm-agent/api-contract.md).

## Установка

Поддерживаются macOS, Ubuntu и Debian. На macOS нужен Homebrew либо уже
установленный Docker Desktop. На Linux достаточно доступа root/sudo. Python,
Node.js и PostgreSQL отдельно устанавливать не нужно.

```bash
git clone https://git.keine-media.com/sorrow9/autoposttg.git
cd autoposttg
./install.sh
```

Скрипт установит или запустит Docker, создаст локальный `.env`, соберёт
контейнеры и проверит доступность приложения.

После установки откройте [http://localhost:8000](http://localhost:8000).
Порт доступен только с текущего компьютера.

## Сервер для стабильной работы

Для одного экземпляра AutoPostTG рекомендуется VPS со следующими ресурсами:

| Ресурс | Минимум для проверки | Рекомендуется для работы |
| --- | --- | --- |
| CPU | 2 vCPU | 4 vCPU |
| RAM | 4 ГБ | 8 ГБ |
| Диск | 20 ГБ SSD | 40 ГБ SSD |
| ОС | Ubuntu 22.04/24.04 или Debian 12 | Ubuntu 24.04 LTS |

Рекомендуемая конфигурация учитывает PostgreSQL, сборку Docker-образа, медиа и
запас для обновлений. Использование CPU и RAM под нагрузкой не измерялось;
нагрузочное тестирование не проводилось. Стоимость и латентность генерации
одного поста также не измерены. Требуемый диск растёт вместе с размером пула
изображений.

Серверу нужен исходящий HTTPS-доступ к Telegram, выбранному AI-провайдеру и
реестрам Docker. По умолчанию UI привязан к `127.0.0.1` и не открыт в интернет.
Для доступа с рабочего компьютера используйте SSH-туннель:

```bash
ssh -L 8000:127.0.0.1:8000 user@server
```

После подключения откройте [http://localhost:8000](http://localhost:8000).

Чтобы открыть UI наружу, задайте в `.env`:

```dotenv
AUTOPOST_BIND=0.0.0.0
POSTIFY_TRUSTED_HOSTS=IP-или-домен-сервера,127.0.0.1,localhost
```

После `docker compose up -d app` интерфейс будет доступен на порту `8000`.
Вход при этом всё равно требует подтверждения в Telegram.

## Первичная настройка

### 1. Подключите бота авторизации

Вход и регистрация идут через Telegram-бота: почты, паролей и общего пароля
доступа нет, личность пользователя — его `telegram_user_id`. Без токена бота
приложение не запускается — войти было бы нечем.

Укажите бота в `.env` (отдельного из `@BotFather` или общего с FakeTG):

```dotenv
AUTH_BOT_TOKEN=токен-бота
AUTH_BOT_USERNAME=имя_бота_без_собаки
AUTH_BOT_RELAY_URL=
AUTH_ALLOWED_TELEGRAM_IDS=
```

`AUTH_ALLOWED_TELEGRAM_IDS` — список `telegram_user_id` через запятую. Пустое
значение означает открытый вход: аккаунт получит любой, кто нашёл бота и
подтвердил вход. Непустой список ограничивает вход перечисленными id.

Telegram допускает только один `getUpdates` на токен. Для общего бота
FakeTG принимает обновления, а AutoPostTG забирает свою очередь по
`AUTH_BOT_RELAY_URL`: полный URL `/_auth/autoposttg/updates` на FakeTG.
Доступ защищён ключом, вычисляемым из общего токена бота; сессии приложений
остаются независимыми. Команды AutoPostTG имеют префикс `autopost_login_`,
FakeTG — `login_`. При недоступности очереди AutoPostTG повторяет запрос,
прямой опрос Telegram не запускается.

Для удалённого адреса требуется HTTPS. Локальная разработка может использовать
SSH-туннель, например `ssh -N -L 127.0.0.1:18080:127.0.0.1:8080 user@server`
и `AUTH_BOT_RELAY_URL=http://127.0.0.1:18080/_auth/autoposttg/updates`.
На одну очередь запускают один процесс AutoPostTG. Очередь FakeTG хранит
до 5000 обновлений в памяти на 10 минут; после перезапуска FakeTG
незавершённый вход при необходимости начинают заново.

При пустом `AUTH_BOT_RELAY_URL` AutoPostTG опрашивает Telegram напрямую:
в этом режиме нужен отдельный бот без другого опрашивающего процесса или вебхука.

Вход выглядит так: браузер показывает ссылку на бота, бот спрашивает «Это я?»,
после подтверждения браузер получает сессионную cookie на год.

### 2. Подключите AI

По умолчанию используется Codex. Авторизация сохраняется в Docker volume:

```bash
docker compose exec app codex login --device-auth
```

Для OpenRouter укажите в `.env`:

```dotenv
CONTENT_ANALYZER=openrouter
OPENROUTER_API_KEY=ключ
OPENROUTER_MODEL=google/gemini-3.1-flash-lite
OPENROUTER_EMBEDDING_MODEL=openai/text-embedding-3-small
```

После изменения `.env` пересоздайте приложение:

```bash
docker compose up -d app
```

### 3. Настройте проект

В интерфейсе создайте проект, подключите к нему бота и канал публикации,
задайте промпт проекта и режим публикации (ревью или автопубликация), загрузите
изображения в пул проекта и заполните контент-план.

## Стек

| Компонент | Технологии | Назначение |
| --- | --- | --- |
| Backend | Python 3.12, FastAPI, Uvicorn | API, UI и планировщик |
| Хранилище | PostgreSQL 17 с pgvector, SQLAlchemy, Alembic | Данные, поиск изображений, миграции |
| Telegram | Telegram Bot API | Вход пользователей и публикация |
| AI | Codex CLI, OpenRouter API | Генерация текста, подписи и эмбеддинги изображений |
| Frontend | React, Vite, shadcn/ui, TypeScript | Интерфейс контент-плана |
| Инфраструктура | Docker, Docker Compose, uv | Сборка и запуск |

## Архитектура

```text
контент-план -> агент (текст + изображение из пула) -> слои проверок
                                  |                          |
                           Web-интерфейс          ревью или автопубликация
                                                             |
                                                     Telegram-канал
```

Один процесс приложения обслуживает UI, планировщик и бота авторизации.
PostgreSQL не публикует порт на хосте. База, медиа и ключ шифрования
сохраняются в Docker volumes.

## Управление

Состояние и логи:

```bash
docker compose ps
docker compose logs -f app
```

Перезапуск и остановка:

```bash
docker compose restart app
docker compose down
```

`docker compose down` сохраняет данные. Команда `docker compose down -v`
удалит базу, медиа, ключ шифрования и AI-авторизацию.

## Разработка

Код из `src/` подключён в контейнер с hot reload. Собранный фронтенд лежит в
`src/postify/web/static/` и коммитится, поэтому обновление прода не требует
пересборки образа.

Тесты запускаются в отдельной временной базе:

```bash
docker compose --profile test build test
docker compose --profile test run --rm test
```

Технический Python namespace пока называется `postify`.
