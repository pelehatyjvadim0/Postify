# Спецификация стека локального MVP

## Цель

Запускать Postify на локальной Ubuntu одной командой в фоне, смотреть состояние отдельной командой и полностью останавливать сервис, когда он не нужен. Решение должно без изменения кода переноситься на VPS.

## Принятый стек

| Область | Решение |
| --- | --- |
| Язык и версия | Python 3.12 |
| Управление зависимостями | uv |
| База данных | PostgreSQL 16 |
| Доступ к БД | SQLAlchemy и Psycopg |
| Миграции | Alembic |
| HTTP-клиент | HTTPX |
| Конфигурация | Pydantic Settings и `.env` |
| Команды | Typer |
| Тестирование | Pytest |
| Фоновое выполнение | systemd service и systemd timer |

Docker и контейнеры не используются.

## Запуск и остановка

CLI-утилита `postify` управляет systemd-unit'ами через штатные команды Ubuntu.

```text
postify start
  → проверяет конфигурацию и миграции
  → запускает PostgreSQL
  → включает и запускает timer Postify

timer по расписанию
  → запускает короткую задачу postify run-once
  → задача выполняет работу и завершается

postify status
  → показывает состояние PostgreSQL и timer
  → показывает последнее/следующее выполнение, счётчики и последнюю ошибку

postify stop
  → отключает timer
  → ждёт текущую задачу
  → останавливает PostgreSQL
```

Python-процесс не запущен между срабатываниями timer. После `postify stop` данные остаются в PostgreSQL, но Postify и PostgreSQL не используют ресурсы машины. Команды управления PostgreSQL могут запросить пароль `sudo`.

## Переносимость

Приложение не содержит логики для локальной машины или VPS. Среда задаётся конфигурацией:

- `DATABASE_URL` определяет подключение к PostgreSQL;
- Telegram-токен и ID группы хранятся в `.env`;
- расписание, параметры Algolia и будущий OpenRouter задаются переменными окружения;
- одна и та же последовательность миграций Alembic применяется локально и на VPS;
- systemd-unit остаётся одинаковым по смыслу, меняются только пользователь и файл окружения.

## Компоненты

| Компонент | Назначение |
| --- | --- |
| Адаптер источника | Получает кандидаты из HN Algolia. |
| Сервис отбора | Нормализует, оценивает и дедуплицирует кандидаты. |
| Репозитории | Сохраняют кандидаты, решения, очередь, публикации и ошибки. |
| Адаптер генерации | В будущем создаёт русскоязычный пост через OpenRouter. До передачи ключа отключён. |
| Адаптер публикации | Отправляет готовые посты в существующую Telegram-группу через Bot API. |
| Планировщик | Вызывает короткую задачу по расписанию. |

Первый источник — HN Algolia. Материалы поступают преимущественно на английском; будущая генерация создаёт содержательную русскоязычную адаптацию, а не дословный перевод. Codex используется для разработки, но не является зависимостью запущенного сервиса.

## Надёжность

- Повторный запуск задачи безопасен: уникальный ключ источника и журнал публикаций исключают дубли.
- Ошибка Algolia, Telegram или OpenRouter сохраняется в журнале и БД; следующее выполнение проходит по расписанию.
- Внешние интеграции заменяемы: бизнес-логика не зависит от конкретного API.
- Рабочие секреты не попадают в репозиторий.

## Проверка первого технического этапа

1. `postify start` запускает PostgreSQL и timer.
2. Задача получает кандидаты из HN Algolia и сохраняет их в PostgreSQL.
3. `postify status` отображает состояние и количество импортированных кандидатов.
4. `postify stop` останавливает timer и PostgreSQL без потери данных.

Тестами покрываются преобразование ответа Algolia, дедупликация, решение о публикации, Telegram-адаптер на подставном HTTP-клиенте и команды CLI без обращения к внешним сервисам.
