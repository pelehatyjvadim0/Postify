# Спецификация стека локального MVP

## Цель

Запускать Postify на локальной Ubuntu одной командой в фоне, смотреть состояние отдельной командой и останавливать задачи Postify, когда они не нужны. Решение должно без изменения кода переноситься на VPS.

## Принятый стек

| Область | Решение |
| --- | --- |
| Язык и версия | Python 3.12 |
| Управление зависимостями | uv |
| База данных | PostgreSQL 16 |
| Доступ к БД | SQLAlchemy и Psycopg |
| Миграции | Alembic |
| HTTP-клиент | HTTPX |
| Конфигурация | Pydantic Settings и `.env` |
| Команды | Typer |
| Тестирование | Pytest |
| Фоновое выполнение | systemd service и systemd timer |

Docker и контейнеры не используются.

## Запуск и остановка

CLI-утилита `postify` управляет systemd-unit'ами Postify и явно настроенным unit'ом PostgreSQL через штатные команды Ubuntu. Имя PostgreSQL-unit задаётся `POSTGRESQL_SYSTEMD_UNIT`, локальное значение по умолчанию — `postgresql.service`.

```text
postify start
  → запускает настроенный PostgreSQL-unit
  → проверяет конфигурацию, доступность БД и применённость миграций
  → включает и запускает timer Postify

timer по расписанию
  → запускает короткую задачу postify run-once
  → задача выполняет работу и завершается

postify status
  → показывает доступность БД и состояние timer
  → показывает последнее/следующее срабатывание, число кандидатов и последний результат задачи

postify stop
  → отключает timer
  → ждёт активную задачу Postify до конечного timeout
  → останавливает настроенный PostgreSQL-unit
```

Python-процесс не запущен между срабатываниями timer. После `postify stop` данные остаются в PostgreSQL.

Используется режим system unit. Установщик получает абсолютные пути к окружению и `EnvironmentFile`, а также пользователя службы, и подставляет их в unit-файлы. `POSTGRESQL_SYSTEMD_UNIT` и режим владения `dedicated` либо `shared_allowed` обязательны: общий экземпляр допускается только при явном осознанном разрешении оператора, потому что `postify stop` остановит его для всех клиентов. При timeout активной задачи PostgreSQL не останавливается.

## Переносимость

Приложение не содержит логики для локальной машины или VPS. Среда задаётся конфигурацией:

- `DATABASE_URL` определяет подключение к PostgreSQL;
- Telegram-токен и ID группы появятся в файле окружения только в волне публикации;
- запрос HN Algolia, расписание, имя PostgreSQL-unit и режим владения задаются переменными окружения; параметры будущего генератора появляются только после выбора провайдера;
- одна и та же последовательность миграций Alembic применяется локально и на VPS;
- systemd-unit остаётся одинаковым по смыслу, меняются только пользователь и файл окружения.

## Компоненты

| Компонент | Назначение |
| --- | --- |
| Адаптер источника | Получает кандидаты из HN Algolia. |
| Сервис отбора | Нормализует и оценивает кандидаты; дедупликация хранения выполняется при импорте. |
| Репозитории | Сохраняют только сущности уже реализованной волны. |
| Адаптер генерации | В будущем создаёт русскоязычный пост через OpenRouter. До передачи ключа отключён. |
| Адаптер публикации | Отправляет готовые посты в существующую Telegram-группу через Bot API. |
| Планировщик | Вызывает короткую задачу по расписанию. |

Первый источник — HN Algolia. Материалы поступают преимущественно на английском; будущая генерация создаёт содержательную русскоязычную адаптацию, а не дословный перевод. Codex используется для разработки, но не является зависимостью запущенного сервиса.

## Надёжность

- Повторный запуск задачи безопасен: уникальный ключ источника и журнал публикаций исключают дубли.
- До волны наблюдаемости ошибка доступна в журнале systemd и завершает запуск с ненулевым кодом; с волны наблюдаемости она дополнительно сохраняется в БД. Следующее срабатывание timer не зависит от предыдущей ошибки.
- Внешние интеграции заменяемы: бизнес-логика не зависит от конкретного API.
- Рабочие секреты не попадают в репозиторий.

## Проверка первого технического этапа

1. `postify start` запускает настроенный PostgreSQL-unit, проверяет доступность и актуальность миграций, затем включает timer.
2. Задача получает кандидаты из HN Algolia и сохраняет их в PostgreSQL.
3. `postify status` отображает доступность БД, timer, последнее/следующее срабатывание, число кандидатов и результат задачи; расширенные счётчики появляются только в волне 5.
4. `postify stop` останавливает timer, дожидается активной задачи и затем останавливает настроенный PostgreSQL-unit без потери уже зафиксированных данных; при timeout PostgreSQL остаётся запущенным.

В каждой волне тесты сначала проходят независимую проверку качества и устойчивости к намеренным мутациям, затем — проверку кода свежим reviewer Terra 5.6 с уровнем рассуждений high. Тестами текущей волны покрываются нормальный путь, ошибки и идемпотентность её сценария; тесты будущих Telegram и генератора не создаются заранее.
