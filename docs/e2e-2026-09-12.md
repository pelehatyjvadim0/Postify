## Найденные проблемы

1. **Неверное число можно одобрить после ручной правки.** Тема: `Хранение зерна. Цена: 130 рублей.` Правка: `Цена: 30 рублей.` Grounding возвращает `supported`, `validation.passed=true`, запрос одобрения — HTTP 200. Причина в проверке вхождения подстроки. Регрессионный тест: `test_manual_edit_does_not_accept_a_number_inside_another_number`. Он сначала упал на `(True, 200) != (False, 409)`, затем помечен строгим ожидаемым падением, чтобы известный дефект оставался видимым. Исправления нет.
2. **Grounding блокирует достоверную перефразировку.** Тема: `Зелёный квадрат на белом фоне.` Текст: `На белом фоне изображён зелёный квадрат.` Реальный судья извлекает всё предложение как claim; буквальное сравнение с темой даёт `unsupported`. Формат и изображение проходят. Та же проблема не дала одобрить реальную генерацию OpenRouter даже после двух ремонтов. [Отчёт позитивного контроля](e2e/2026-09-12/guardrail-supported-paraphrase.json), [первый текст](e2e/2026-09-12/openrouter-post.json), [переписанный текст](e2e/2026-09-12/openrouter-rewritten-post.json).
3. **Codex не выполнил операции через адаптер приложения.** Отдельно испробованы извлечение правил и создание поста; обе операции получили `failed`. Создание проверялось несмотря на предшествующий сбой извлечения правил. Установленный лимит одного вызова — 90 секунд; весь сценарий до результата генерации занял 140,52 секунды, включая извлечение правил и загрузку двух изображений. API сохраняет общие коды ошибок, поэтому по этим данным нельзя достоверно назвать первопричину таймаутом. [Извлечение правил](e2e/2026-09-12/codex-derive.json), [генерация](e2e/2026-09-12/codex-generation-operation.json).

## Воспроизведение

Обычные сценарии требуют тестовую PostgreSQL и собранную SPA. `TEST_DATABASE_URL` должен указывать на отдельную тестовую БД с доступным pgvector. Каждый integration-тест создаёт и удаляет свою схему.

```bash
PYTHONPATH=src python -m pytest tests/integration/test_feature_workflow.py tests/integration/test_browser_workflow.py -q
```

Реальные провайдеры включаются явно. `OPENROUTER_API_KEY` передаётся в окружении, для Codex нужна действующая локальная авторизация CLI. По умолчанию live-тесты пропускаются.

```bash
AUTOPOST_LIVE_E2E=1 AUTOPOST_E2E_PROVIDERS=openrouter,codex PYTHONPATH=src \
  python -m pytest tests/integration/test_live_agent_workflow.py -vv
```

Публикация отдельно требует `AUTOPOST_E2E_CHANNEL_FILE`: путь к приватному JSON с `chat_id` и `bot_token` **явно разрешённого тестового канала**. Без него Telegram-тест пропускается. Файл с токеном не добавлять в Git; тест удаляет собственное опубликованное сообщение через `finally`. `AUTOPOST_E2E_REPORT_DIR` задаёт каталог JSON-отчётов без токенов.

Продакшен AutoPostTG не обновлялся, пользовательские проекты не изменялись. Нагрузочные испытания, длительная работа планировщика и независимая проверка произвольных фактов по внешним источникам в этот прогон не входили. Фактическая стоимость запросов провайдеров не измерялась.

После прогона отдельная тестовая БД и временные локальные/серверные файлы с токеном удалены. Локальные frontend и backend остаются доступны по http://127.0.0.1:5174/.
