# RED-доказательство Wave 3

## Граница

База: `wave-3-content-packages@fde7c53`, исходное подтверждённое состояние
`Sₙ = main@b88ba02`. Пакет содержит только тесты Wave 3 и это
доказательство. Production-код, конфигурация, README и план не изменены.

Целевой переход: `selected → content attempt → article body → Codex batch →
content package → awaiting_review/approved/rejected`, без Telegram, UI и AI-генерации
изображений.

## Карта 12 mutation gates

| № | Неверная реализация | Узкий RED-gate |
| ---: | --- | --- |
| 1 | Превысить 12 анализов или 3 пакета при повторном/конкурентном run | `test_claim_enforces_daily_limit_and_never_claims_candidate_twice`, `test_two_concurrent_claims_share_budget_without_duplicates`, `test_concurrent_package_reservation_never_exceeds_three`, domain batch limit |
| 2 | Сделать каждый день 11/1, потерять долг пустого класса | три `test_weighted_credits_*`/`test_empty_reserve_*` и `test_postgresql_weighted_claim_persists_exact_54_6_over_five_days` |
| 3 | Повторно взять candidate; создать duplicate attempt/package в гонке | два claim concurrency nodes, duplicate AI IDs, concurrent package reservation |
| 4 | Анализировать только HN title/snippet | `test_extracted_article_requires_body_beyond_title_and_snippet`, `test_extract_prefers_article_text_and_discards_page_chrome`, `test_partial_article_failure_schedules_one_retry_and_analyzes_real_body`, `test_codex_exec_receives_article_body_and_hardened_invocation` |
| 5 | Claim retry до 6 часов, не учесть его в лимите или сделать третью попытку | `test_due_retry_waits_six_hours_consumes_slot_and_second_failure_is_terminal`, attempt number nodes, два article-failure action nodes |
| 6 | Обойти review-required, не auto-approve, разрешить terminal transition | review-policy nodes, transition matrix, invalid review nodes, atomic repository review |
| 7 | Включить source URL в post или скрыть audit-поля из show | `test_post_text_must_not_contain_source_url`, invalid Codex payload URL, `test_content_show_prints_complete_auditable_package`, full repository package |
| 8 | Нарушить og/twitter/article/Wikimedia, MIME/size, safe path или atomic write | article image-order node, все media acquisition/validation/path nodes, Wikimedia node |
| 9 | Удалить active media до Telegram, не удалить при reject/TTL или потерять retry delete | approve/reject/delete nodes, `test_cleanup_removes_only_expired_unprotected_files`, process cleanup/media-failure nodes |
| 10 | Раскрыть network/Codex/filesystem/SQL секрет или оставить ненаблюдаемое state | transport normalization, Codex failure, process failure codes, failed delete, safe CLI error, SQL rollback nodes |
| 11 | Съесть budget/credit на rollback; оставить partial package/history | `test_claim_sql_failure_rolls_back_usage_quota_and_attempts`, `test_package_history_sql_failure_rolls_back_analysis_package_and_budget`, atomic repository review |
| 12 | Потерять Alembic head в wheel | `test_built_wheel_contains_wave_three_alembic_head`; schema/downgrade отдельно защищены migration node |

Покрытие design mutation gates: `12/12`. Фактическое поочерёдное внесение мутаций
выполняет независимый reviewer после GREEN.

## Отклонения карты файлов

- `tests/integration/test_import_component.py`: только механически добавлены значения
  новых mandatory `Settings` в helper и inline wheel-процесс. Assertions и поведение retained
  nodes не изменены.
- `tests/__init__.py`, `tests/unit/__init__.py`, `tests/unit/domain/__init__.py`,
  `tests/unit/domain/candidates/__init__.py`, `tests/unit/domain/content/__init__.py`: только
  test-package markers. Они устраняют pytest import collision двух обязательных
  `test_models.py`; production/package discovery не меняют.
- `tests/unit/infrastructure/test_content_wheel.py`: узкий non-integration gate вынесен
  из integration-модуля, чтобы проверка wheel не требовала PostgreSQL.

## Риски для GREEN-исполнителя

- Контракт `save_analysis_and_create_packages` явно получает local `day` и
  `package_limit`: иначе нельзя атомарно доказать gate 1.
- `processing → approved` разрешён только для `review_required=false`; обычный
  review остаётся `processing → awaiting_review → approved/rejected`.
- PostgreSQL concurrency nodes намеренно проверяют один суточный row lock и
  уникальности; in-memory GREEN не заменяет эту границу.
- Codex constructor/API зафиксирован подменяемым runner; не нужно запускать
  настоящий `codex` для GREEN.
