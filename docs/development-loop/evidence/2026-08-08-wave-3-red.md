## Риски для GREEN-исполнителя

- Контракт `save_analysis_and_create_packages` явно получает local `day` и
  `package_limit`: иначе нельзя атомарно доказать gate 1.
- `processing → approved` разрешён только для `review_required=false`; обычный
  review остаётся `processing → awaiting_review → approved/rejected`.
- PostgreSQL concurrency nodes намеренно проверяют один суточный row lock и
  уникальности; in-memory GREEN не заменяет эту границу.
- Codex constructor/API зафиксирован подменяемым runner; не нужно запускать
  настоящий `codex` для GREEN.
